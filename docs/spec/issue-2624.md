# Spec #2624 — Sprachauflösung als geteilter Helper, /next ohne Nutzer-Abfrage im Leerfall

Server-Refaktoring ohne Verhaltensänderung: Die Kette App-Sprache auflösen (`User.sprache`, sonst
`Accept-Language`, #2523) steht doppelt im Produktivcode (`loeseSprache` in `routes/scores.ts` und
inline in `GET /next`, `express/index.ts:505-506`). Sie wird zu einem geteilten, puren Helper
`appSprache` in `routes/geoConfig.ts` (direkt neben `resolveGeoUser`) zusammengelegt; `GET /next`
kehrt bei leerem Ergebnis (`200` + `null`) bereits VOR `resolveGeoUser` zurück und stellt dann
keine Nutzer-Abfrage mehr an.

| AK  | Voraussetzung                                                                    | Erwartung                                                                                                                                                                                                                                                                                                                                                             |
| --- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Helper `appSprache(user, req)` in `routes/geoConfig.ts`; user = Nutzer oder null | Nutzer vorhanden → `spracheVon(user.sprache)` (Nutzer gewinnt gegen Header, auch bei `sprache: null`); Nutzer null → `spracheAusHeader(req.get('accept-language'))`. „Genau einmal im Produktivcode, beide Aufrufstellen (`loeseSprache`, `/next`) rufen denselben Helper“ ist Review-Befund; das Verhalten beider Endpunkte sichern die Bestandstests (#2523-Block). |
| 2   | registrierter Nutzer ohne offene Tasks, `GET /next`                              | `200` + `null`; die Route stellt keine Nutzer-Abfrage an: gleich viele `User`-Abfragen wie eine Kontroll-Anfrage ohne Nutzer-Auflösung (`/suggestions`, gleicher Cookie) — ohne Früh-Return wäre es genau eine mehr (`resolveGeoUser`).                                                                                                                               |
| 3   | registrierter Nutzer mit offener Aufgabe, `GET /next` mit Treffer                | unverändert: Säulennamen folgen der App-Sprache (#2523), `reasons.split` folgt `splitHintEnabled` (#1994), der `res.locals.saeulenSprache`-Override bleibt wirksam; ein einziger `resolveGeoUser`-Aufruf bedient alles.                                                                                                                                               |
| 4   | Bestandstests #2523/#2527                                                        | `scores-care-suggestions.test.ts` und `suggestions.test.ts` bleiben unverändert grün — inkl. `?sprache=`-Override am Care-Endpunkt (bleibt exklusiv dort; `/next` bekommt keinen Override).                                                                                                                                                                           |
